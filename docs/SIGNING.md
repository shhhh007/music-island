# Подпись и статус выпуска

Публичный выпуск 1.0.0 не подписан. Исправления текста песен и оптимизации в `main` не означают, что старые файлы релиза были заменены. Новый стабильный выпуск должен пройти проверку подписи и запуск на Windows с включённой защитой.

Smart App Control может перейти из режима оценки в режим применения политики. Тогда ранее запускавшийся неподписанный файл может быть заблокирован. Это само по себе не является обнаружением вируса. [Документация Microsoft](https://learn.microsoft.com/en-us/windows/apps/develop/smart-app-control/overview).

## Сборка для подписанного выпуска

Нужен действующий доверенный RSA-сертификат Code Signing с доступным закрытым ключом в `Cert:\CurrentUser\My`. Сертификат оформляет издатель приложения. Закрытый ключ не экспортируется скриптом и не должен попадать в Git, чат или пакет.

В Windows PowerShell задайте отпечаток своего сертификата и адрес сервера временных меток, предоставленный вашим центром сертификации:

```powershell
./package.ps1 -RequireSignature -SigningCertificateThumbprint YOUR_CERTIFICATE_THUMBPRINT -TimestampServer http://YOUR_PROVIDER_TIMESTAMP_ENDPOINT
```

Сборка проверяет цепочку доверия и срок сертификата до создания пакета. Подписываются все EXE, DLL и PS1 в промежуточном каталоге, затем установщик. Проверяются подписи и временные метки; контрольные суммы вычисляются после подписи. При ошибке процесс останавливается. Исходники в рабочем каталоге не подписываются и не меняются.

Без параметров подписи остаётся сборка для разработки; она не обещает совместимость с Smart App Control. Самодельный сертификат, переименование файла и контрольная сумма не заменяют доверенную подпись. Скрипт не меняет политики Windows и не добавляет исключения.

## Проверки перед стабильным выпуском

1. Выполнить `test-lyrics.ps1` под Windows PowerShell 5.1 и `test.ps1` на рабочем столе Windows.
2. Собрать пакет с `-RequireSignature` и выполнить `tools/verify-package.ps1`.
3. Проверить установку, запуск, обновление, удаление, медиакнопки и текст с реальным плеером на отдельном ПК с включённой защитой.
4. Публиковать новый стабильный релиз только после успешных проверок. Подпись подтверждает издателя и целостность; она не гарантирует отсутствие всех ошибок или срабатываний защиты.

В текущей среде нет сертификата издателя, а запуск EXE заблокирован политикой Windows. Поэтому подписанный выпуск и его проверка запуска пока не выполнены. Подписание с настоящим сертификатом требует отдельной проверки после его оформления.
